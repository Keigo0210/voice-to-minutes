# 3階層エージェント連携（Gemini Argon × Gemini Flash × Codex CLI）と自律委任方針

チャット画面の親エージェントは常時 **Gemini 4 Argon** に固定し、ユーザーのモデル切り替えの手間をゼロにしつつ、週間リミットしかない Argon のターン数とコンテキスト消費を極小化するため、以下の **3階層アーキテクチャ** で自律運用する。詳細手順は `codex-cli` スキルに従う。

## 1. 3階層の役割分担（Argon → Flash → Codex CLI）

1. **親エージェント（Gemini 4 Argon）：テックリード・設計・最終品質承認**
   - ユーザーの要求理解、要件定義、アーキテクチャ設計、仕様と受け入れ条件の決定。Ponytail 原則に基づき、過剰な抽象化や先回りの設計を排除し、最小限の仕様を策定する。
   - 実作業（複数ステップの調査・実装進行・Codex CLI の呼び出しと待機・一次レビュー・ビルド・Git操作等）は、自身でツールを何ターンも回さず、**`invoke_subagent(TypeName: "self", Model: "flash")`（軽微な定型確認なら `flash_lite`）を1回呼び出して Flash サブエージェントへ一括委任**する（※ユーザーからの明示指示により、`invoke_subagent` での `Model: "flash"` / `"flash_lite"` 指定を常時許可する）。
   - Flash サブエージェントから返却された「本番コード差分（`git diff`）」と検証結果を受け取り、設計・品質・Ponytail 遵守（過剰コードの有無）の最終チェックを行ってユーザーへ報告する（**Argon 自身は原則 1〜2 ターンしか動かない**）。
2. **中継ぎサブエージェント（Gemini Flash）：現場監督・Codex 進行・実務代行**
   - 5時間回復枠を持つ Flash が独立した短いコンテキストで起動し、泥臭い複数ターンのツール実行をすべて引き受ける。
   - `codex-cli` スキルに従い、Codex CLI（`codex exec`）のプロンプトに Ponytail 原則（7段階ラダー）を自動注入して実行・待機・結果取得（`/tmp/codex-last-message.txt`）を行う。
   - `git diff -- src/ worker/ domain/ shared/` と境界部分の一次チェックを行い、不要な抽象化・重複・過剰コードがないかを点検する。問題があれば `codex exec resume --last`（最大2回）や軽微な `edit_file`、再テスト・ビルド（`npm run build`）までを Flash のスレッド内で完結させる。
   - 完了後、親（Argon）が自身の目で最終確認できるよう、**「変更ファイル一覧・本番コードの `git diff`（テスト除く）・検証結果サマリ・Ponytail スキップ報告」** を親へ返す。
3. **実働エージェント（Codex CLI）：コード探索・実装・テスト作成・自己検証**
   - OpenAI 側の利用枠を使って、既存コードの広い探索、Ponytail 7段階ラダーに基づく最小コード実装、リファクタリング、テスト作成と実行（`typecheck` / `lint` / `test`）を自律完結させる。
   - 完了報告の末尾に「スキップした事項（不要と判断した処理やファイル）」を明記する。
   - 要件変更や重要な設計変更が必要になった場合は、独断で進めず選択肢を返させる。

## 2. タスク規模に応じた自律ルーティング基準

- **パターンA（通常の実装・調査・複数ステップ作業）**：**Argon → Flash サブエージェント → Codex CLI**
  - Argon が仕様を固め、`invoke_subagent(TypeName: "self", Model: "flash")` に委任し、Flash が Codex CLI を駆動して実装・検証・（指示があればコミット/デプロイまで）を完遂する。
- **パターンB（コマンド実行のみの定型作業：コミット・プッシュ・デプロイ・軽微な調査）**：**Argon → Flash（または `flash_lite`）サブエージェント**
  - コード実装を伴わない複数コマンドの実行やWeb/ドキュメント調査（`research` サブエージェント等）も、`Model: "flash"`（または `flash_lite`）のサブエージェントに任せて Argon のターン消費を防ぐ。
  - ※ ただし、本当に 1 回のツール呼び出しだけで即終わる操作は、サブエージェント起動の往復（2ターン）を避けて Argon が直接 1 コマンドで処理してよい。
- **パターンC（質問回答・設計相談・1箇所の数行修正）**：**Argon 単独**
  - ツールをほぼ使わない対話や、すでに開いているファイルの2〜3行の修正は Argon がその場で直接行う（この場合も Ponytail 原則に従い最小差分で修正する）。

## 3. Ponytail 原則：怠惰なシニア開発者モード（過剰エンジニアリング防止とトークン最小化）

「**書かずに済むコードが最良のコード（The best code is the code you never wrote）**」を全階層の最優先行動指針とする。
すべての設計・調査・実装タスクにおいて、以下の **7段階の怠惰ラダー（7-Rung Ladder of Laziness）** を上から順に評価し、要求を満たす**最初の段**で思考・実装を停止する。

1. **YAGNI（不要なものを作らない）**: 要求されていない機能、将来への先回り、投機的オプションは一切書かない。
2. **既存再利用（Reuse）**: 既存の関数、型定義、CSSクラス、UIコンポーネント、ユーティリティを最優先で再利用する。
3. **標準機能（Standard Library）**: 言語標準（JS/TS組み込みメソッド、Date、URL、RegExp等）でシンプルに解く。
4. **ネイティブ機能（Native Platform）**: ブラウザ標準API（HTML5タグ、ネイティブ入力、DOM）やWorkersランタイム標準で済ませる（自作ラッパーを作らない）。
5. **既存依存関係（Installed Dependencies）**: 新規 npm パッケージは導入せず、プロジェクト既存の依存ライブラリで解決する。
6. **ワンライナー（One Line）**: 意図が一目で伝わる簡潔な1行コードで表現できるなら1行で書く。
7. **最小限の実装（Minimum Viable Code）**: 上記で満たせない場合のみ、仕様を満たす必要最小限のコードを書く。

### 守るべき防衛線（Lazy, Not Negligent）
怠惰は過剰な抽象化に対してであり、安全性・正確性に対してではない。以下は絶対に削らない：
- 信頼境界の入力バリデーション（Trust-boundary validation）
- データ損失防止・必須のエラーハンドリング（Data-loss handling & Error recovery）
- セキュリティ・認可境界（Security & Core access control）
- アクセシビリティ・必須の動作検証（typecheck / lint / test）

### 最小差分と透明性報告（Accountability Tracing）
- **不要な新規ファイル・不要なラッパーの禁止**: 1回限りのロジックのために専用クラスや新規抽象化ファイルを作らず、既存ファイルへの局所追加にとどめる。
- **スキップ報告の義務化**: 各エージェント（Argon / Flash / Codex）は回答末尾に1〜2行で **「スキップした事項（不要と判断した抽象化やファイル等）」** と潜在リスクを簡潔に明記する。

## 4. 品質管理と安全制約（全階層共通）

- **実装状態の確実な把握**：Flash サブエージェントは完了報告に必ず本番コードの変更差分（`git diff -- src/ worker/ domain/ shared/`）を含め、Argon はその差分を自分の目で確認してからユーザーに完了報告する。
- **大量ログの遮断**：`npm test` や `npm run build`、`codex exec` の大量出力は `/tmp/*.log` に逃がし、Argon にも Flash にも全文を読み込ませない。
- **外部通信コマンド（`gh` 等）の1発実行**：`gh` コマンド等の外部通信・認証を伴うコマンドは、失敗前提のサンドボックス内試行を省き最初から `BypassSandbox: true` で実行する。また出力の省略（`...`）による再取得を防ぐため、最初から `--json` オプション等で必要情報を1回のコマンドで取得する。
- **承認必須の操作**：本番デプロイ（`wrangler deploy` / `npm run deploy`）、リモートDBの破壊的・書き込み操作（`wrangler d1 ... --remote`）、`git push`、認証情報の公開は、ユーザーの明示的な承認がある場合のみ実行する（ユーザーから「実装してコミット・プッシュ・デプロイして」と明示指示された場合は、Flash サブエージェントにそこまで一括実行させてよい）。
